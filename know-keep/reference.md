# know-keep 参考文档

## 模式详解

### 1. 对话提取模式 (--chat)

**适用场景**: 日常对话后快速提取学到的知识点

**流程**:
1. 分析当前会话所有消息
2. 识别可复用的知识模式
3. 抽象提炼 → 写入知识库

**优势**: 无需扫描文件，快速直接

**触发短语**（任意时刻可用）:
- "记一下..."
- "记住这个..."
- "这个很重要..."
- "以后都这样..."

### 2. 规则归纳模式 (--归纳)

**适用场景**: 同类知识超过 3 条时，提炼通用规则

**核心价值**: 避免知识库变成零散案例堆砌，保持检索有效性

**流程**:
1. 扫描知识库，识别同类知识（相同关键词、相似场景）
2. 提炼通用规则，保留 1-2 个典型示例
3. 将原条目降级为 L2 详情（不删除，保留追溯）
4. **高风险审核**: 展示归纳前后对比，请求用户确认

**归纳示例**:
```
输入: 5 条零散知识
• 时区转换用 pytz
• 数据库时区设 UTC
• 前端显示用本地时间
• API 返回带时区戳
• 日志时间统一格式

输出: 1 条通用规则
• 时区一致性 ⭐⭐⭐
  > 统一 Asia/Shanghai，边界处转换
  详情降级到 L2（保留 2 个典型示例）
```

**触发条件**:
- 手动调用: `/know-keep --归纳`
- 自动建议: 检测到同类知识 ≥3 条时提示

### 3. 会话快照模式 (--snapshot)

**适用场景**: 保存关键决策，支持后续追溯

**核心价值**: 弥补情景记忆缺失，决策有据可查

**流程**:
1. 提取当前会话的关键决策
2. 生成快照文件到 `~/.kb/sessions/`
3. 更新索引

**快照格式** (`~/.kb/sessions/YYYY-MM-DD-topic.yaml`):
```yaml
date: 2026-03-01
topic: ai-news 代理配置
decisions:
  - choice: 使用本地 Claude 解读替代外部 OpenAI API
    reason: 避免第三方 API 调用，保持架构简洁
    alternatives: [调用 OpenAI API, 使用其他第三方服务]
files:
  - fetch_news.py
  - SKILL.md
context: 国内网络环境需要代理访问
```

**查询快照**:
```bash
/know-keep --snapshot --query "ai-news"
```

### 4. Flomo 同步模式 (--flomo)

**适用场景**: 将核心知识同步到 flomo，便于碎片化回顾

**核心价值**: 知识库 + flomo 双轨沉淀，flomo 做轻量回顾

**筛选标准**: 仅同步重要性 ⭐⭐⭐ 的核心知识

**执行流程**:
1. 读取 `~/.kb/config.yaml` 获取 flomo API 地址
2. 扫描所有知识文件，筛选 ⭐⭐⭐ 条目
3. 格式化为 flomo 格式（自动添加标签）
4. 通过 API 发送到 flomo

**Flomo 格式**:
```
[知识标题] - 一句话原则 #claude #know-keep

[可选：关键要点或示例]
```

**API 调用**:
```bash
curl -X POST "$FLOMO_API" \
  -H "Content-Type: application/json" \
  -d '{"content": "知识内容 #claude #know-keep"}'
```

**安全措施**:
- API 地址存储在 `~/.kb/config.yaml`（不被 git 追踪）
- 每日限制 100 条（flomo API 限制）
- 同步前显示预览，确认后发送

**配置方式**:
```yaml
# ~/.kb/config.yaml
storage_path: ~/.kb
created: 2026-02-27
flomo_api: https://flomoapp.com/iwh/xxx/xxx/
```

### 5. 知识同步模式 (--sync)

**目标**: 将高频知识沉淀到 `~/.claude/CLAUDE.md`

**筛选标准**:
1. 高频使用 - 每次对话都可能用到
2. 通用原则 - 不依赖特定项目
3. 用户偏好 - 工作流、编码规范

**执行流程**:
1. 读取 `~/.kb/` 所有知识文件
2. 读取 `~/.claude/CLAUDE.md` 当前内容
3. 分析每条知识，标记推荐级别
4. 输出分析表格，逐条确认
5. 用户确认后写入

**推荐级别**:
| 标记 | 含义 | 条件 |
|------|------|------|
| ✅ 推荐 | 合并 | 符合全部筛选标准 |
| ⚠️ 可选 | 询问 | 部分符合，看使用频率 |
| ❌ 不适合 | 跳过 | 项目特定/低频 |

### 5. 压缩模式 (--compress)

**触发条件**: 知识库条目超过 50 条时建议使用

**操作**:
1. 合并相似条目
2. 降级详情 L2 → L1
3. 清理过期知识（90天未访问且重要性 ⭐）

## 高风险审核机制

### 审核触发条件

| 风险等级 | 触发条件 | 示例 |
|----------|----------|------|
| ⚠️ 覆盖 | 新规则与现有规则冲突 | 新"提交规范"覆盖旧规范 |
| ⚠️ 删除 | 标记知识过时或删除 | 删除已废弃的工具知识 |
| ⚠️ 归纳 | 合并 3+ 条同类知识 | 5 条时区知识合并为 1 条 |

### 审核流程

```
⚠️ 检测到高风险操作

操作类型: 规则归纳
影响范围: 5 条知识 → 1 条通用规则

归纳前:
• 时区转换用 pytz
• 数据库时区设 UTC
• ...

归纳后:
• 时区一致性 ⭐⭐⭐
  > 统一 Asia/Shanghai，边界处转换
  L2 详情保留 2 个典型示例

是否继续? [Y/n/编辑]:
```

### 审核选项

- `Y` - 确认执行
- `n` - 跳过此操作
- `编辑` - 手动修改归纳结果

## 配置说明

### 首次运行

1. 检查 `~/.kb/config.yaml` 是否存在
2. 不存在 → 询问用户选择存储位置
3. 写入配置，后续严格遵守

### 路径选项

| 选项 | 路径 | 特点 |
|------|------|------|
| user | ~/.kb | 跨项目共享（推荐） |
| project | ./.kb | 跟随当前项目 |

> 一旦配置确定，后续运行必须严格遵守，不得随意更改

**计算方法**:
- 中文: chars / 4
- 英文: chars / 6
- 总计 = 输入 + 输出

## 最佳实践

### 日常使用

1. **即时记录**: 对话中说"记一下"立即触发，不要等会话结束
2. **定期归纳**: 每周运行 `--归纳`，避免知识碎片化
3. **关键决策快照**: 重要架构决策后立即 `--snapshot`

### 避坑指南

1. **不让知识无限堆砌** - 同类知识 ≥3 条时必须归纳
2. **不跳过高风险审核** - 覆盖/删除操作必须确认
3. **不依赖自动归纳** - LLM 不会主动归纳，需显式触发
