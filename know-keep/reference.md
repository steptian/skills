# know-keep 参考文档

## 模式详解

### 1. 对话提取模式 (--chat)

**适用场景**: 日常对话后快速提取学到的知识点

**流程**:
1. 分析当前会话所有消息
2. 识别可复用的知识模式
3. 抽象提炼 → 写入知识库

**优势**: 无需扫描文件，快速直接

**触发短语**（任意时刻可用）:
- "记一下..."
- "记住这个..."
- "这个很重要..."
- "以后都这样..."

### 2. 文件夹提取模式 (--from-dir)

**适用场景**: 从笔记文件夹、文档目录批量提取知识

**核心价值**: 将散落的文档知识沉淀为可复用的结构化知识

**支持文件类型**: `.md`, `.txt`, `.rst`, `.org`, `.html`, `.htm`

**HTML 处理**:
- 直接读取本地 HTML 文件，不依赖 MCP 工具
- 解析 HTML 结构，提取 `<div class="content">` 等正文内容
- 自动过滤 `<script>`、`<style>`、导航等非正文元素
- 保留结构化信息（标题、列表、表格）

**执行流程**:
1. 扫描指定目录，识别文本文件
2. 逐个读取文件内容
3. 提取可复用的知识模式（设计决策、最佳实践、踩坑经验）
4. 归纳总结，合并同类知识
5. 写入知识库，标注来源文件

**筛选规则**:
- 跳过: 配置文件、日志、临时文件
- 提取: 设计文档、会议记录、学习笔记、技术总结
- 忽略: 具体代码实现、项目特定配置

**目录规模处理**:
| 文件数 | 处理方式 |
|--------|----------|
| < 20 | 直接扫描全部 |
| 20-50 | 显示文件列表，用户选择 |
| > 50 | 警告，建议缩小范围 |

**示例**:
```bash
# 从笔记文件夹提取
/know-keep --from-dir ~/Documents/notes

# 从项目文档提取
/know-keep --from-dir ./docs

# 从会议记录提取
/know-keep --from-dir ~/meetings
```

**输出格式**:
```
文件夹提取 | 目录: ~/notes
文件: 15 个 | 有效: 12 个

提取完成:
• 知识点 A ⭐⭐⭐ (来自 meeting-2026-02.md)
• 知识点 B ⭐⭐ (来自 tech-notes.md)
• 归纳规则 C (合并自 3 个文件)

新增: 5 条 | 归纳: 2 条 | 跳过: 8 条
```

### 3. 规则归纳模式 (--归纳)

**适用场景**: 同类知识超过 3 条时，提炼通用规则

**核心价值**: 避免知识库变成零散案例堆砌，保持检索有效性

**流程**:
1. 扫描知识库，识别同类知识（相同关键词、相似场景）
2. 提炼通用规则，保留 1-2 个典型示例
3. 将原条目降级为 L2 详情（不删除，保留追溯）
4. **高风险审核**: 展示归纳前后对比，请求用户确认

**归纳示例**:
```
输入: 5 条零散知识
• 时区转换用 pytz
• 数据库时区设 UTC
• 前端显示用本地时间
• API 返回带时区戳
• 日志时间统一格式

输出: 1 条通用规则
• 时区一致性 ⭐⭐⭐
  > 统一 Asia/Shanghai，边界处转换
  详情降级到 L2（保留 2 个典型示例）
```

**触发条件**:
- 手动调用: `/know-keep --归纳`
- 自动建议: 检测到同类知识 ≥3 条时提示

### 3. 会话快照模式 (--snapshot)

**适用场景**: 保存关键决策，支持后续追溯

**核心价值**: 弥补情景记忆缺失，决策有据可查

**流程**:
1. 提取当前会话的关键决策
2. 生成快照文件到 `~/.kb/sessions/`
3. 更新索引

**快照格式** (`~/.kb/sessions/YYYY-MM-DD-topic.yaml`):
```yaml
date: 2026-03-01
topic: ai-news 代理配置
decisions:
  - choice: 使用本地 Claude 解读替代外部 OpenAI API
    reason: 避免第三方 API 调用，保持架构简洁
    alternatives: [调用 OpenAI API, 使用其他第三方服务]
files:
  - fetch_news.py
  - SKILL.md
context: 国内网络环境需要代理访问
```

**查询快照**:
```bash
/know-keep --snapshot --query "ai-news"
```

### 4. Flomo 同步模式 (--flomo)

**适用场景**: 将核心知识同步到 flomo，便于碎片化回顾

**核心价值**: 知识库 + flomo 双轨沉淀，flomo 做轻量回顾

**筛选标准**: 仅同步重要性 ⭐⭐⭐ 的核心知识

**执行流程**:
1. 读取 `~/.kb/config.yaml` 获取 flomo API 地址
2. 扫描所有知识文件，筛选 ⭐⭐⭐ 条目
3. 格式化为 flomo 格式（自动添加标签）
4. 通过 API 发送到 flomo

**Flomo 格式**:
```
[知识标题] - 一句话原则 #claude #know-keep

[可选：关键要点或示例]
```

**API 调用**:
```bash
curl -X POST "$FLOMO_API" \
  -H "Content-Type: application/json" \
  -d '{"content": "知识内容 #claude #know-keep"}'
```

**安全措施**:
- API 地址存储在 `~/.kb/config.yaml`（不被 git 追踪）
- 每日限制 100 条（flomo API 限制）
- 同步前显示预览，确认后发送

**配置方式**:
```yaml
# ~/.kb/config.yaml
storage_path: ~/.kb
created: 2026-02-27
flomo_api: https://flomoapp.com/iwh/xxx/xxx/
```

### 5. 知识同步模式 (--sync)

**目标**: 将高频知识沉淀到 `~/.claude/CLAUDE.md`

**筛选标准**:
1. 高频使用 - 每次对话都可能用到
2. 通用原则 - 不依赖特定项目
3. 用户偏好 - 工作流、编码规范

**执行流程**:
1. 读取 `~/.kb/` 所有知识文件
2. 读取 `~/.claude/CLAUDE.md` 当前内容
3. 分析每条知识，标记推荐级别
4. 输出分析表格，逐条确认
5. 用户确认后写入

**推荐级别**:
| 标记 | 含义 | 条件 |
|------|------|------|
| ✅ 推荐 | 合并 | 符合全部筛选标准 |
| ⚠️ 可选 | 询问 | 部分符合，看使用频率 |
| ❌ 不适合 | 跳过 | 项目特定/低频 |

### 6. 知识晋升模式 (--promote)

**核心价值**: 将经过验证的高价值知识自动晋升到全局配置，减少重复学习

**与 --sync 的区别**:
- `--sync`: 人工审查，逐条确认
- `--promote`: 基于数据驱动的自动推荐

**晋升条件**（满足任意 2 条）:

| 条件 | 阈值 | 说明 |
|------|------|------|
| 访问次数 | ≥ 5 | 被频繁查阅 |
| 验证次数 | ≥ 2 | 在不同场景下成功应用 |
| 跨项目 | ≥ 2 | 来源包含多个项目 |
| 重要性 | ⭐⭐⭐ | 核心知识 |

**晋升目标**:
```
~/.claude/CLAUDE.md
├── ## 工作规范        # 工作流、编码规范
├── ## 技术偏好        # 技术选型、工具配置
└── ## 用户偏好        # 沟通风格、输出格式
```

**执行流程**:
1. 扫描知识库，计算每条知识的晋升得分
2. 筛选得分 ≥ 2 的候选条目
3. 读取 CLAUDE.md，检查是否已存在类似内容
4. 展示候选列表，按得分排序
5. 用户逐条确认
6. 确认后：
   - 追加到 CLAUDE.md 适当章节
   - 原条目标记 `[已晋升]`
   - 添加 `晋升到: CLAUDE.md#章节` 元数据

**晋升得分计算**:
```
得分 = (访问 >= 5 ? 1 : 0) +
       (验证 >= 2 ? 1 : 0) +
       (跨项目 >= 2 ? 1 : 0) +
       (重要性 == 3 ? 1 : 0)
```

**输出格式**:
```
📋 知识晋升检查 | ~/.kb

晋升候选 (得分 >= 2):
┌──────────────────────────────────────────────────┐
│ ✅ 文档同步策略 ⭐⭐⭐ [已验证]                   │
│    > 架构变→CLAUDE.md，功能变→progress.md        │
│    得分: 4 | 访问: 8 | 验证: 3 | 跨项目: 2       │
│    推荐: CLAUDE.md#工作规范                      │
├──────────────────────────────────────────────────┤
│ ⚠️ 提交信息规范 ⭐⭐ [已验证]                    │
│    > feat/fix/style + 功能描述 + 影响模块        │
│    得分: 2 | 访问: 5 | 验证: 1 | 跨项目: 1       │
│    推荐: CLAUDE.md#工作规范 (可选)               │
└──────────────────────────────────────────────────┘

已晋升 (跳过):
• Claude Skill 开发规范 - 已在 CLAUDE.md 中存在

是否晋升以上知识? [Y/n/选择]:
```

**晋升后处理**:
```markdown
## 文档同步策略 ⭐⭐⭐ [已晋升]

> 架构变→CLAUDE.md，功能变→progress.md，Bug修→*_FIX.md

---
来源: conversation | 提取: 2026-02-27 | 访问: 8次 | 验证: 3次
晋升到: CLAUDE.md#工作规范 | 晋升时间: 2026-03-03
```

### 5. 压缩模式 (--compress)

**触发条件**: 知识库条目超过 50 条时建议使用

**操作**:
1. 合并相似条目
2. 降级详情 L2 → L1
3. 清理过期知识（90天未访问且重要性 ⭐）

## 高风险审核机制

### 审核触发条件

| 风险等级 | 触发条件 | 示例 |
|----------|----------|------|
| ⚠️ 覆盖 | 新规则与现有规则冲突 | 新"提交规范"覆盖旧规范 |
| ⚠️ 删除 | 标记知识过时或删除 | 删除已废弃的工具知识 |
| ⚠️ 归纳 | 合并 3+ 条同类知识 | 5 条时区知识合并为 1 条 |

### 审核流程

```
⚠️ 检测到高风险操作

操作类型: 规则归纳
影响范围: 5 条知识 → 1 条通用规则

归纳前:
• 时区转换用 pytz
• 数据库时区设 UTC
• ...

归纳后:
• 时区一致性 ⭐⭐⭐
  > 统一 Asia/Shanghai，边界处转换
  L2 详情保留 2 个典型示例

是否继续? [Y/n/编辑]:
```

### 审核选项

- `Y` - 确认执行
- `n` - 跳过此操作
- `编辑` - 手动修改归纳结果

## 配置说明

### 首次运行

1. 检查 `~/.kb/config.yaml` 是否存在
2. 不存在 → 询问用户选择存储位置
3. 写入配置，后续严格遵守

### 路径选项

| 选项 | 路径 | 特点 |
|------|------|------|
| user | ~/.kb | 跨项目共享（推荐） |
| project | ./.kb | 跟随当前项目 |

> 一旦配置确定，后续运行必须严格遵守，不得随意更改

## 最佳实践

### 日常使用

1. **即时记录**: 对话中说"记一下"立即触发，不要等会话结束
2. **定期归纳**: 每周运行 `--归纳`，避免知识碎片化
3. **关键决策快照**: 重要架构决策后立即 `--snapshot`

### 避坑指南

1. **不让知识无限堆砌** - 同类知识 ≥3 条时必须归纳
2. **不跳过高风险审核** - 覆盖/删除操作必须确认
3. **不依赖自动归纳** - LLM 不会主动归纳，需显式触发
