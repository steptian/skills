# daily-plan - 每日待办计划与日程管理

> 四象限优先级 + 时段分配 + 固定日程 + 智能估算 + 持续复盘

## 时区规范

**所有时间统一使用 `Asia/Shanghai` 时区**

- 获取当前日期：`date +%Y-%m-%d`（系统已配置上海时区）
- 获取当前时间：`date +%H:%M`
- 文件命名、时间戳、统计周期均以上海时间为准

## 快速开始

```bash
/daily-plan              # 创建/查看今日计划
/daily-plan --review     # 每日复盘
/daily-plan --week       # 每周总结
/daily-plan --add "任务" # 快速添加任务
/daily-plan --done 3     # 标记任务 3 完成
/daily-plan --schedule   # 查看今日日程
```

**日程管理**（自然语言触发）：
```
"下午两点面试"        → 自动创建日程
"明天10点开会"        → 自动创建日程到明天
"把面试改到3点"       → 修改日程时间
"取消下午的会议"      → 删除日程
```

## 意图解析

收到用户输入后，按以下优先级路由到对应操作：

### 参数模式（`/daily-plan` 带参数）

| 参数 | 操作 | 示例 |
|------|------|------|
| (无参数) | 创建/查看今日计划 | `/daily-plan` |
| `--review` | 每日复盘 | `/daily-plan --review` |
| `--week` | 每周总结 | `/daily-plan --week` |
| `--add "任务"` | 添加任务 | `/daily-plan --add "完成文档 🔴"` |
| `--done ID` | 标记完成（支持逗号分隔多个ID） | `/daily-plan --done 3` 或 `--done 1,2,5` |
| `--schedule` | 查看今日日程 | `/daily-plan --schedule` |
| `--reschedule ID 时间` | 修改日程时间 | `/daily-plan --reschedule 3 14:00` |

### 自然语言模式（无参数时解析意图）

按优先级从高到低匹配，命中即执行：

**P0 — 日程操作**（含明确时间 + 事件关键词）：
```
"下午两点面试"          → 添加日程（解析日期+时间，写入 calendar/ + macOS日历）
"明天10点开会"          → 添加日程到明天
"把面试改到3点"         → reschedule（模糊匹配日程名称）
"取消下午的会议"        → 标记日程 ✕
```

**P1 — 完成标记**（含完成意图）：
```
"完成了" / "做完了" / "搞定了"   → 查找最近/当前任务，询问确认后标记 ●
"任务3完成了"                    → 直接标记 ID=3 为 ●
```

**P2 — 添加任务**（含任务添加意图）：
```
"今天要做 X" / "加个任务 X" / "记个任务" → 添加任务到今日计划
```

**P3 — 复盘/总结**（含复盘意图）：
```
"今日复盘" / "今天总结" / "今天回顾" → 执行每日复盘
"周总结" / "这周复盘"                → 执行每周总结
```

**P4 — 查看计划**（默认行为）：
```
"今天安排" / "今日计划" / "上班了" / "开始工作" → 创建或查看今日计划
```

### 解析流程图

```
用户输入
  ├─ 含 --参数? → YES → 执行参数对应操作
  └─ NO → 依次匹配 P0→P1→P2→P3→P4
          ├─ P0: 含明确时间(点/点半/:XX/下午X点)? → 日程操作
          ├─ P1: 含完成词(完成/做完/搞定)? → 标记完成
          ├─ P2: 含添加词(要做/加个/记个)? → 添加任务
          ├─ P3: 含复盘词(复盘/总结/回顾)? → 复盘/周总结
          └─ P4: 默认 → 创建/查看今日计划
```

### 时间解析规则

日程操作时，从用户输入提取时间：
- **相对日期**："今天"→当天，"明天"→+1天，"后天"→+2天，"下周X"→下个周X
- **相对时间**："X点"→整点，"X点半"→:30，"下午X点"→X+12点
- **绝对时间**："14:00"、"下午2:30" → 直接使用
- **默认时长**：面试/会议类 1h，其他 30min（用户可指定）

## 任务 vs 日程（核心区分）

| 维度 | 任务（弹性） | 日程（固定时间） |
|------|-------------|-----------------|
| 时间 | 有预估时长，无固定时间 | 有明确的开始/结束时间 |
| 特征 | "今天要做"，自由安排 | "X点X分开会"，不可调整 |
| 存储 | `daily/YYYY-MM-DD.md` | `calendar/YYYY-MM.md` |
| 示例 | "重构 pig-gen 项目" | "下午14:00 面试" |
| 标识 | 无固定时间标记 | 任务详情中有 `固定时间` 标记 |

**自动识别规则**：当用户说出的时间包含以下模式时，自动识别为日程：
- "X点"、"X点半"、"X:XX"、"下午X点"、"上午X点"
- "明天X点"、"下周X X点"
- "面试"、"开会"、"会议"、"约了"、"碰头"、"排了"

### 日程操作

**添加日程**：用户说出有时间的事件时，自动执行：
1. 解析日期和时间（今天/明天/具体日期）
2. 检查时间冲突
3. 写入 `calendar/YYYY-MM.md`
4. 同步到当日计划的时间线

**修改日程**：用户说"改到X点"、"推迟半小时"时：
1. 找到匹配的日程（按名称模糊匹配）
2. 检查新时间是否冲突
3. 更新日程表和当日计划
4. 显示变更前后对比

**取消日程**：用户说"取消了"、"不用了"时：
1. 状态改为 `✕`
2. 保留记录（不删除），标注取消原因
3. 从当日计划时间线中移除

**冲突检测**：
- 新日程与已有日程时间重叠时，提醒用户
- 显示冲突的两个日程，让用户选择调整

## 本机日历同步（macOS Calendar）

日程除了写入 `calendar/` markdown 记录，还要同步到 macOS 日历，方便系统提醒。

**双写策略**：
- `calendar/YYYY-MM.md`：作为记录保存，支持搜索和复盘
- macOS Calendar：用于系统通知提醒，手机/手表同步

**使用脚本操作**（避免 AppleScript 中文编码问题）：

脚本位置：`scripts/calendar.sh`（相对于 skill 目录）

```bash
# 添加日程（含提醒）
bash <skill-path>/scripts/calendar.sh add "steptian@tencent.com" "面试" "2026-04-13 14:00" "2026-04-13 14:30" "前端工程师" 15

# 删除日程
bash <skill-path>/scripts/calendar.sh delete "steptian@tencent.com" "面试" "2026-04-13 14:00"

# 查看某月日程
bash <skill-path>/scripts/calendar.sh list "steptian@tencent.com" 2026 4
```

**参数说明**：
- 日历名：默认 `添先盼`（已验证可写入）
- 时间格式：`YYYY-MM-DD HH:MM`
- 提醒分钟：默认 15，可自定义

**日历选择**：默认 `添先盼`（经测试，"计划的提醒事项"日历有同步问题），如果用户指定其他日历则使用指定日历。

**提醒设置**：
- 默认提前 15 分钟提醒
- 用户可指定："提前半小时提醒"、"提前1小时提醒"

|------|------|------|
| pending | `○` | 待办 |
| in_progress | `◐` | 进行中 |
| done | `●` | 已完成 |
| deferred | `↻` | 已延期 |
| cancelled | `✕` | 已取消 |
| blocked | `⊘` | 阻塞中 |

## 四象限分类

| **重要** | 🔴 立即做 | 🟡 计划做 |
| **不重要** | 🟠 委托/快速处理 | 🟢 可不做 |

## 执行流程

1. **收集任务**：扫描项目 TODO + 结转未完成 + 用户输入 + 知识库关联
2. **区分类型**：固定时间的事件 → 日程表；弹性任务 → 四象限
3. **分类排序**：四象限 + 时段分配（日程时间作为硬约束排入时间线）
4. **时间估算**：基于历史数据智能估算（仅对弹性任务）
5. **冲突检测**：检查日程之间、日程与弹性任务时间是否有冲突
6. **输出计划**：保存到文件（日程写入 calendar/，任务写入 daily/）+ 对话展示
7. **状态追踪**：记录状态变化时间
8. **日程同步**：固定时间事件 → 写入 markdown 日程表 + macOS 日历
9. **询问打开**：处理完成后，询问用户是否用 mdg 打开对应的 md 文档，确认则执行 `mdg <文件路径>`

详细流程见 [reference.md](./reference.md)，示例见 [examples.md](./examples.md)。

## 复盘知识关联

**复盘时自动检查知识库**:
1. 扫描 `~/.kb/` 中标注为 `[验证中]` 的知识
2. 检测任务中是否已验证某条知识
3. 发现问题模式时建议提取知识
4. 检查是否有知识符合晋升条件

**知识提取建议**:
```
复盘发现可提取知识:
• "数据库连接超时" 处理方案 → tech-arch.md
• "API 文档规范" 最佳实践 → workflow.md

是否提取? [Y/n]:
```

**晋升提醒**:
```
📋 检测到 2 条知识符合晋升条件:
• 时区一致性 ⭐⭐⭐ (访问: 6次, 验证: 2次)
• 文档同步策略 ⭐⭐⭐ (访问: 8次, 验证: 3次)

建议运行: /know-keep --promote
```
