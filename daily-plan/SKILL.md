# daily-plan - 每日待办计划

> 四象限优先级 + 时段分配 + 智能估算 + 持续复盘

## 时区规范

**所有时间统一使用 `Asia/Shanghai` 时区**

- 获取当前日期：`date +%Y-%m-%d`（系统已配置上海时区）
- 获取当前时间：`date +%H:%M`
- 文件命名、时间戳、统计周期均以上海时间为准

## 快速开始

```bash
/daily-plan              # 创建/查看今日计划
/daily-plan --review     # 每日复盘
/daily-plan --week       # 每周总结
/daily-plan --add "任务" # 快速添加任务
/daily-plan --done 3     # 标记任务 3 完成
```

## 存储结构

```
~/.daily-plan/
├── daily/
│   ├── 2026-02-27.md    # 今日计划
│   └── 2026-02-26.md    # 历史记录
├── weekly/
│   └── 2026-W09.md      # 周总结
└── stats.json           # 统计数据（智能估算用）
```

## 任务状态

| 状态 | 符号 | 含义 |
|------|------|------|
| pending | `○` | 待办 |
| in_progress | `◐` | 进行中 |
| done | `●` | 已完成 |
| deferred | `↻` | 已延期 |
| cancelled | `✕` | 已取消 |
| blocked | `⊘` | 阻塞中 |

## 四象限分类

| | 紧急 | 不紧急 |
|--|------|--------|
| **重要** | 🔴 立即做 | 🟡 计划做 |
| **不重要** | 🟠 委托/快速处理 | 🟢 可不做 |

## 任务格式

### 存储格式（文件内）

```markdown
- [id] ○ 🔴 任务描述 (预估: 1h) [项目]
  - 来源: 知识库 product-design.md
  - 时段: 上午
  - 阻塞: 无
  - 创建: 09:00
```

### 展示格式（表格）

```markdown
| # | 状态 | 优先级 | 任务描述 | 预估 | 来源 |
|---|------|--------|----------|------|------|
| 1 | ○ | 🔴 | 物流自动填充 | 3h | 知识库 |
| 2 | ○ | 🟡 | 代码审查 | 1h | 项目TODO |
| 3 | ○ | 🟠 | 回复邮件 | 0.5h | 用户输入 |
```

### 任务来源标识

| 来源 | 标识 | 说明 |
|------|------|------|
| 结转 | `结转` | 昨日未完成任务 |
| 项目TODO | `项目TODO` | `**/TODO.md` 扫描 |
| 知识库 | `知识库` | `~/.kb/*.md` 关联内容 |
| 用户输入 | `用户输入` | 用户直接告知 |

## 执行流程

1. **收集任务**：扫描项目 TODO + 结转未完成 + 用户输入 + 知识库关联
2. **分类排序**：四象限 + 时段分配
3. **时间估算**：基于历史数据智能估算
4. **输出计划**：保存到文件 + 对话展示
5. **状态追踪**：记录状态变化时间
6. **询问打开**：处理完成后，询问用户是否用 mdg 打开对应的 md 文档，确认则执行 `mdg <文件路径>`

详细流程见 [reference.md](./reference.md)，示例见 [examples.md](./examples.md)。

## 复盘知识关联

**复盘时自动检查知识库**:
1. 扫描 `~/.kb/` 中标注为 `[验证中]` 的知识
2. 检测任务中是否已验证某条知识
3. 发现问题模式时建议提取知识
4. 检查是否有知识符合晋升条件

**知识提取建议**:
```
复盘发现可提取知识:
• "数据库连接超时" 处理方案 → tech-arch.md
• "API 文档规范" 最佳实践 → workflow.md

是否提取? [Y/n]:
```

**晋升提醒**:
```
📋 检测到 2 条知识符合晋升条件:
• 时区一致性 ⭐⭐⭐ (访问: 6次, 验证: 2次)
• 文档同步策略 ⭐⭐⭐ (访问: 8次, 验证: 3次)

建议运行: /know-keep --promote
```
