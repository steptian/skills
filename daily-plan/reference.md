# daily-plan 参考文档

## 模式详解

### 1. 创建计划 (默认模式)

**触发条件**:
- 手动 `/daily-plan`
- 每日首次对话时自动建议
- 早上时段自动提示

**任务收集来源**:

| 来源 | 优先级 | 说明 |
|------|--------|------|
| 结转未完成 | 1 | 昨天未完成的任务自动结转 |
| 项目扫描 | 2 | TODO.md、progress.md、*.todo |
| 知识库关联 | 3 | ~/.kb 中标记的任务 |
| 用户输入 | 4 | 自然语言描述 |

**四象限判断逻辑**:

```
重要 = 影响核心目标/有价值产出
紧急 = 有截止日期/不处理会恶化

🔴 重要+紧急 → 立即处理
🟡 重要+不紧急 → 计划时间做
🟠 不重要+紧急 → 快速处理/委托
🟢 不重要+不紧急 → 考虑不做
```

**时段分配规则**:

| 时段 | 时间 | 适合任务 |
|------|------|----------|
| 上午 | 9:00-12:00 | 🔴 重要紧急、需要专注 |
| 下午 | 14:00-18:00 | 🟡 重要不紧急、沟通协作 |
| 晚上 | 19:00-22:00 | 🟢 不重要、学习复盘 |

**智能时间估算**:

基于 `~/.daily-plan/stats.json` 历史数据：
1. 匹配相似任务关键词
2. 取历史平均时长的 1.2 倍
3. 无匹配时使用默认估算（30min）

### 2. 每日复盘 (--review)

**触发条件**:
- 手动 `/daily-plan --review`
- 晚上时段（20:00后）自动提示
- 检测到用户说"今天结束了"、"复盘"

**分析维度**:

1. **完成率统计**
   - 总任务数 / 完成数
   - 按象限分类统计
   - 实际耗时 vs 预估

2. **问题模式识别**
   - 连续延期任务（3天+）
   - 高频阻塞任务
   - 低完成率时段

3. **容量分析**
   - 平均日完成量
   - 高效时段识别
   - 建议日任务数

**输出内容**:
- 完成率统计
- 象限分布
- 问题模式警告
- 明日建议

### 3. 每周总结 (--week)

**触发条件**:
- 手动 `/daily-plan --week`
- 周五晚上自动提示
- 用户说"周总结"、"这周复盘"

**分析内容**:

1. **周完成率趋势**
   - 每日完成率折线
   - 周平均完成率

2. **任务类型分布**
   - 按象限统计
   - 按项目统计

3. **效率模式**
   - 最高效日期
   - 最佳工作时段
   - 典型阻塞原因

4. **下周建议**
   - 容量规划
   - 时段优化
   - 任务类型调整

### 4. 快速操作

**--add 添加任务**:
```
/daily-plan --add "完成 API 文档"
/daily-plan --add "下午开会 🔴"
```

自动解析：
- 优先级标记（🔴🟡🟠🟢）
- 时段关键词（上午/下午/晚上）
- 项目名称（从当前目录推断）

**--done 标记完成**:
```
/daily-plan --done 3
/daily-plan --done 1,2,5
```

记录完成时间，更新统计数据。

## 状态追踪

每个状态变化都会记录时间戳：

```markdown
- [3] ● 🔴 完成 API 文档 (实际: 1.5h) [skills]
  - 时段: 上午
  - 状态流: ○ 09:00 → ◐ 09:30 → ● 11:00
```

**阻塞记录**:
```markdown
- [4] ⊘ 🟡 数据库优化 (阻塞中)
  - 阻塞原因: 等待 DBA 权限
  - 阻塞时间: 2026-02-27 10:00
  - 解决方案: 联系运维处理
```

## 与其他 Skill 联动

| Skill | 联动方式 |
|-------|----------|
| know-keep | 复盘时提取知识、检查晋升候选 |
| commit | 任务完成后提示提交 |
| code-review | 代码审查任务自动添加 |

### 复盘关联 know-keep

**触发时机**: 每日复盘 (--review) 时自动执行

**检查内容**:

1. **验证中知识检查**
   - 扫描 `~/.kb/` 中 `[验证中]` 状态的知识
   - 对比今日任务，识别已验证的知识
   - 更新知识的验证次数

2. **问题模式提取**
   - 识别连续延期 3+ 天的任务
   - 识别高频阻塞原因
   - 建议提取为知识条目

3. **晋升候选检查**
   - 计算每条知识的晋升得分
   - 筛选得分 ≥ 2 的候选
   - 提醒用户运行 `/know-keep --promote`

**复盘输出增强**:
```markdown
📚 知识关联:
├── 已验证知识: 2 条
│   • 文档同步策略 - 今日项目中应用
│   • 提交信息规范 - 3 次提交中应用
├── 可提取知识: 1 条
│   • "数据库连接超时" 处理方案
└── 晋升候选: 2 条
    • 时区一致性 ⭐⭐⭐ (得分: 3)
    • Claude Skill 开发规范 ⭐⭐⭐ (得分: 4)
```

**交互流程**:
```
复盘发现 1 条问题模式可提取为知识:
• "数据库连接超时" 处理方案

是否提取? [Y/n/详情]: Y

✓ 已提取到 ~/.kb/tech-arch.md
  标题: 数据库连接超时处理 ⭐⭐
  状态: [验证中]
```

**晋升提醒格式**:
```
📋 检测到 2 条知识符合晋升条件

运行 /know-keep --promote 查看详情
```
