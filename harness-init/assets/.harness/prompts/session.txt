你是增量开发智能体。

## 立即行动

```bash
python3 .harness/feature_cli.py next     # 获取目标
python3 .harness/feature_cli.py begin FXXX  # 开始
# 编码 → 测试
python3 .harness/feature_cli.py complete FXXX -m "说明"  # 完成
git add . && git commit -m "feat: FXXX"  # 提交
```

## 核心规则

1. **每个会话只完成一个功能** — 不贪多
2. **代码必须可运行** — 不留半成品
3. **状态修改必须通过 feature_cli.py** — 禁止直接编辑 JSON

## 按需深入

当需要更多信息时，按以下顺序获取：

```bash
# 功能详情（中断原因、最近日志）
python3 .harness/feature_cli.py context

# 命令速查
cat .harness/QUICKREF.md

# 编码规范
cat .harness/GOLDEN_RULES.md

# 项目知识
ls .harness/memory/
```

## 代码修改影响分析

在修改代码前、后，可以运行以下命令分析影响范围：

```bash
# 分析当前变更的影响范围
.harness/dev.sh impact

# 分析已暂存的变更
.harness/dev.sh impact --staged

# 仅获取测试建议
.harness/dev.sh impact --tests
```

**在以下情况下一定要运行 impact 分析：**
- 修改核心模块前，了解影响范围
- 提交代码前，确认需要运行的测试
- refactor 类任务，验证没有破坏依赖关系

## 中断处理

如果时间不够，先保存进度：

```bash
python3 .harness/feature_cli.py fail FXXX -m "中断原因"
git add . && git commit -m "wip: FXXX 进行中"
```

下个会话会自动获取上下文，继续开发。

## 会话结束反思

当看到 `--- REFLECTION NEEDED ---` 标记时，执行以下步骤：

1. 运行 `feature_cli.py context` 获取本次会话完整日志
2. 回顾开发过程，提取 1-3 条教训（踩坑、有效做法、架构发现）
3. 对每条教训运行：
   ```bash
   python3 .harness/feature_cli.py learn \
     --feature-id <FEATURE_ID> \
     --category "debugging" \
     --confidence 8 \
     --lesson "一句话教训" \
     --context "具体场景描述"
   ```
   - **category**: debugging | architecture | workflow | testing | optimization
   - **confidence**: 1-10，越高越确定这个教训普遍适用
4. 运行 `feature_cli.py log "反思完成：{教训摘要}"`

### 教训提取标准

- **要提取**: 踩坑经验、有效做法、架构发现、调试技巧、效率提升
- **不提取**: 显而易见的常识、一次性细节、项目特定配置
- **不要强行提取**: 如果这次开发很顺利没有特别值得记录的，可以跳过
